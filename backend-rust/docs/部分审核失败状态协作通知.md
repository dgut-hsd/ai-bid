# 部分审核失败状态协作通知

## 背景

Rust 审核引擎已区分三种终态，防止 Agent 崩溃被包装成审核成功：

- `completed`：所有已路由 Agent 和条款均完整执行。
- `partial_failed`：至少一个 Agent 成功，但存在 Agent 或条款失败；成功结果仍可展示。
- `failed`：所有已路由 Agent 均失败，不返回审核结果。

## Rust 端已提供的契约

`GET /api/v1/review/{doc_id}/result` 在 `partial_failed` 时返回：

```json
{
  "status": "partial_failed",
  "result": {
    "execution_summary": {
      "status": "partial_failed",
      "successful_agents": 1,
      "failed_agents": [{ "agent_id": "AgentA", "message": "..." }],
      "failed_clauses": [
        { "agent_id": "AgentA", "clause_id": "ch_001", "message": "..." }
      ],
      "failed_stages": [
        { "stage": "batch_search", "message": "BatchSearch 阶段超过 120 秒" }
      ],
      "budget": {
        "limits": {
          "llm_calls": 120,
          "tool_calls": 200,
          "web_search_calls": 40,
          "total_tokens": 400000
        },
        "llm_calls": 35,
        "tool_calls": 51,
        "web_search_calls": 18,
        "total_tokens": 182000,
        "exhausted": false,
        "exhausted_reason": null
      }
    }
  }
}
```

SSE 新增终态事件 `partial_done`，字段包括 `total_findings`、`high_risk`、
`session_id`、`duration_secs`、`failed_agents`、`failed_clauses`、`failed_stages` 和
`budget`。全部失败继续发送现有 `error`；完整成功继续发送现有 `done`。

并发限制由 Rust 进程统一管理：全局默认 12、单文档默认 3，可分别通过
`AIBID_GLOBAL_CONCURRENCY` 和 `AIBID_DOCUMENT_CONCURRENCY` 调整。单文档值会被约束为不超过
全局值。Java 不应为每个请求另行启动 Rust 进程，否则全局额度无法跨用户共享。

预算按“Agent 与条款的有效任务对数”动态计算，并设置硬上限：LLM 30～600 次、工具
60～1000 次、联网搜索 10～120 次、Token 10 万～200 万。阶段超时为 BatchSearch 120 秒、
Execute 20 分钟、LegalVerify 5 分钟、Debate 5 分钟，总管线硬上限 30 分钟；单次 LLM/工具
调用为 60 秒，单条款为 180 秒。

## 请 Java 网关配合

- 透传 `partial_failed`，不要改写为 `completed` 或 `failed`。
- 透传 `result.execution_summary` 和 SSE `partial_done` 的全部字段。
- 若网关维护终态白名单，将 `partial_failed`、`partial_done` 加入白名单。
- 保持现有 `error` 的 HTTP/SSE 行为，不为部分失败返回 5xx。
- 不新增用户取消接口；本次仅实现 Rust 内部的超时取消。

## 请前端配合

- 将 `partial_done` 视为终态：停止加载、保留 findings，并显示“审核部分完成”警告。
- 提供失败 Agent/条款明细；不得使用“审核成功”文案。
- 当 `failed_stages` 非空或 `budget.exhausted=true` 时展示具体降级原因和已消耗额度。
- `failed`/`error` 仍展示整体失败且不渲染空结果为“无风险”。
- 对旧后端缺少 `execution_summary` 的响应保持兼容。

## 联调验收

请分别验证：完整成功收到 `done`；单个 Agent 或条款失败收到 `partial_done` 且结果可见；
全部 Agent 失败收到 `error`；刷新后查询结果仍保持同一终态。协作方提交时请附接口样例、测试证据和 commit SHA。

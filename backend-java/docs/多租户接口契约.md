# AI-Bid 多租户后端接口契约

> 契约版本：tenant-v1  
> Schema 版本：1  
> 状态：Frozen  
> 日期：2026-08-06  
> 机器可读定义：[多租户接口 OpenAPI JSON](tenant-openapi.json)

本文件是 Java 后端、Rust 内部代理和外部前端团队之间的交接契约。领域字段和
不变量见 [租户领域模型 ADR](../../docs/adr/tenant-model.md)，隔离、迁移、
签名和回滚见 [租户隔离 ADR](../../docs/adr/tenant-isolation.md)。

## 1. 通用约定

### 1.1 HTTP 和字段

- 外部 API 基础路径为 /api，使用 UTF-8 JSON。
- 新增租户域字段使用 snake_case：tenant_id、role、permissions、
  session_version、request_id。
- Java 数据库 ID 是 BIGINT，在 API、JWT、异步消息和 Header 中均以十进制
  字符串传输。
- 受保护接口使用 Authorization: Bearer <token>。浏览器不得发送 X-Tenant-Id
  作为租户选择依据。
- 可选请求头 X-Request-Id 最长 64 字符；缺失时由 Java 生成 UUID，并在响应、
  审计、异步消息和内部 Rust 调用中沿用。
- 路径中的 tenantId 仅用于定位候选资源，必须与 CurrentTenant 一致。请求体、
  查询参数或路径中的租户值都不能绕过成员关系检查。

### 1.2 统一响应体

Java 沿用现有 Result<T> 外壳。租户域接口保证 code 与 HTTP 状态码一致：

    {
      "code": 200,
      "msg": "success",
      "data": {},
      "timestamp": 1786019400123
    }

错误响应仍使用同一外壳，稳定机器判断使用 data.error_code，不要匹配中文 msg。
request_id 用于向后端查询日志和审计：

    {
      "code": 403,
      "msg": "当前角色无权执行该操作",
      "data": {
        "error_code": "TENANT_ROLE_FORBIDDEN",
        "request_id": "8b9c0e7f-9d8b-4f86-b77d-9a3d4c2f5001",
        "details": {
          "required_permission": "tenant.members.role.write"
        }
      },
      "timestamp": 1786019400123
    }

分页字段固定为 page、size、total、items。page 从 1 开始，size 默认 20，最大 100。

### 1.3 鉴权快照

登录、刷新和切换租户成功后返回的会话数据至少包含：

    {
      "token": "eyJhbGciOiJIUzI1NiJ9...",
      "token_type": "Bearer",
      "expires_in": 86400,
      "session_version": 3,
      "user_info": {
        "user_id": "10001",
        "username": "alice",
        "real_name": "Alice"
      },
      "current_tenant": {
        "tenant_id": "20001",
        "tenant_code": "acme-bid",
        "name": "Acme 招标团队",
        "role": "ADMIN",
        "permissions": [
          "tenant.read",
          "tenant.settings.write",
          "tender.write",
          "audit.start",
          "audit.report.read",
          "knowledge.write"
        ],
        "status": "ACTIVE"
      },
      "tenants": [
        {
          "tenant_id": "20001",
          "tenant_code": "acme-bid",
          "name": "Acme 招标团队",
          "role": "ADMIN",
          "permissions": ["tenant.read", "tender.write"],
          "status": "ACTIVE",
          "is_current": true
        }
      ]
    }

当前 Java 登录对象中的旧 userInfo 字段可以在兼容窗口内保留，但新租户客户端
必须读取 user_info。服务端根据成员表重新计算 role 和 permissions，客户端提交
的同名字段永远不作为授权输入。

## 2. 认证、当前租户和切换

### 2.1 POST /api/auth/login

请求体沿用现有用户名密码登录字段。登录时服务端选择一个 ACTIVE 成员作为
current_tenant：优先使用用户上一次有效租户，否则使用最早加入的 ACTIVE 租户。

登录成功后，客户端必须保存新 token、session_version、租户列表和权限快照。
没有 ACTIVE 成员时允许登录，但 current_tenant 和 tenants 为空；调用需要租户
上下文的业务接口时返回 400 TENANT_REQUIRED。

### 2.2 POST /api/auth/refresh

请求只需要 Authorization Header。刷新会生成新 token，旧 token 立即失效；返回
结构与登录相同，并重新读取用户、租户和成员状态。旧 token 中的 tenant_id
不得覆盖服务端当前会话。

### 2.3 GET /api/tenants

返回当前用户的 ACTIVE、SUSPENDED 和历史 REMOVED 成员摘要。默认只返回可切换的
ACTIVE 租户；include_removed=true 才可返回 REMOVED 记录，且不能用于业务访问。

    {
      "code": 200,
      "msg": "success",
      "data": {
        "current_tenant_id": "20001",
        "items": [
          {
            "tenant_id": "20001",
            "tenant_code": "acme-bid",
            "name": "Acme 招标团队",
            "status": "ACTIVE",
            "role": "ADMIN",
            "permissions": ["tenant.read", "tender.write"],
            "is_current": true
          },
          {
            "tenant_id": "20002",
            "tenant_code": "solo-10001",
            "name": "Alice 个人空间",
            "status": "ACTIVE",
            "role": "OWNER",
            "permissions": ["tenant.read", "tenant.delete"],
            "is_current": false
          }
        ]
      },
      "timestamp": 1786019400123
    }

### 2.4 GET /api/tenants/current

返回当前会话的完整租户摘要，包括 tenant_id、role、permissions、session_version。
没有当前租户时返回 400 TENANT_REQUIRED。

### 2.5 POST /api/tenants/{tenantId}/switch

请求体为空。服务端验证目标租户、成员状态和租户状态后：

1. 递增服务端 session version；
2. 使旧 token 失效；
3. 签发带新 tenant_id、role、permissions 的 token；
4. 返回完整会话数据。

旧 SSE 连接、异步任务和缓存不会自动变换租户。客户端必须关闭旧 SSE、丢弃旧
租户缓存，再使用新 token 建立连接。目标租户不是当前用户成员时统一返回
404 TENANT_NOT_FOUND，不泄露租户存在性。

## 3. 租户 API

| 方法 | 路径 | 所需权限 | 结果 |
|---|---|---|---|
| GET | /api/tenants | 已登录 | 当前用户的租户摘要 |
| POST | /api/tenants | 已登录 | 创建租户并创建 OWNER |
| GET | /api/tenants/current | 有当前租户 | 当前租户和权限 |
| PATCH | /api/tenants/{tenantId} | tenant.settings.write | 修改名称和设置 |
| POST | /api/tenants/{tenantId}/switch | ACTIVE 成员 | 签发新会话 |
| POST | /api/tenants/{tenantId}/transfer-owner | tenant.owner.transfer | 原子转移所有权 |
| POST | /api/tenants/{tenantId}/disable | tenant.settings.write | 停用租户 |
| POST | /api/tenants/{tenantId}/restore | tenant.settings.write | 恢复租户 |
| DELETE | /api/tenants/{tenantId} | tenant.delete | 软删除租户 |

### 3.1 POST /api/tenants

请求：

    {
      "name": "Acme 招标团队",
      "tenant_code": "acme-bid",
      "plan_code": "STANDARD",
      "settings": {
        "timezone": "Asia/Shanghai"
      }
    }

tenant_code 可选时由服务端生成；客户端不能提交 owner_user_id、状态、版本或
tenant_id。成功后当前用户成为唯一 OWNER，并返回完整 Tenant 对象。

### 3.2 PATCH /api/tenants/{tenantId}

只允许修改 name、plan_code 和非敏感 settings。客户端必须发送当前 version，
版本不一致返回 409 TENANT_STATE_INVALID：

    {
      "name": "Acme 投标与审核团队",
      "plan_code": "STANDARD",
      "settings": {
        "timezone": "Asia/Shanghai"
      },
      "version": 4
    }

### 3.3 所有权转移、停用和删除

所有权转移请求：

    {
      "target_user_id": "10002",
      "version": 4
    }

目标用户必须是当前租户的 ACTIVE 成员；操作在一个事务内更新成员角色、
tenant.owner_user_id、session version 和审计日志。停用/恢复请求体为空，删除
请求体可带 version。删除前必须已经转移 OWNER，删除是软删除。

## 4. 成员和邀请 API

| 方法 | 路径 | 所需权限 | 说明 |
|---|---|---|---|
| GET | /api/tenants/{tenantId}/members | tenant.read | 分页列出成员 |
| PATCH | /api/tenants/{tenantId}/members/{userId} | tenant.members.role.write | 修改角色或状态 |
| DELETE | /api/tenants/{tenantId}/members/{userId} | tenant.members.remove | 移除成员，保留历史关系 |
| POST | /api/tenants/{tenantId}/invitations | tenant.members.invite | 创建邀请 |
| GET | /api/tenants/{tenantId}/invitations | tenant.members.invite | 分页列出邀请 |
| DELETE | /api/tenants/{tenantId}/invitations/{invitationId} | tenant.members.invite | 撤销 PENDING 邀请 |
| POST | /api/tenant-invitations/{token}/accept | 已登录 | 接受一次性邀请 |

### 4.1 成员权限响应

成员列表 item 固定包含：

    {
      "member_id": "30001",
      "tenant_id": "20001",
      "user_id": "10002",
      "username": "bob",
      "real_name": "Bob",
      "role": "AUDITOR",
      "permissions": [
        "tenant.read",
        "tender.write",
        "audit.start",
        "audit.report.read",
        "knowledge.write"
      ],
      "status": "ACTIVE",
      "joined_at": "2026-08-06T12:30:00.123Z",
      "last_seen_at": "2026-08-06T13:30:00.123Z"
    }

### 4.2 创建和接受邀请

创建邀请请求：

    {
      "email": "bob@example.com",
      "role": "AUDITOR",
      "expires_in_seconds": 604800
    }

响应只在创建成功时返回一次性 accept_token；数据库只存
SHA-256(accept_token)。生产环境可以通过邮件或其他外部渠道传递 token，但接受
URL 固定为：

    POST /api/tenant-invitations/{token}/accept
    Authorization: Bearer <invitee token>

接受者的登录账号邮箱必须与邀请邮箱规范化后相等。成功接受后创建或恢复
tenant_member，不会自动切换当前租户；客户端随后调用 switch：

    {
      "tenant_id": "20001",
      "member_id": "30002",
      "role": "AUDITOR",
      "status": "ACTIVE",
      "accepted_at": "2026-08-06T13:00:00.123Z"
    }

原始 token 不进入日志、审计 before_json/after_json、异常消息或 Redis key。

## 5. 错误码

code 为 HTTP 状态码；error_code 是稳定值。跨租户资源和无权查看的资源统一
使用 404 RESOURCE_NOT_FOUND。

| HTTP | error_code | 语义 |
|---:|---|---|
| 400 | REQUEST_INVALID | JSON、路径或参数校验失败 |
| 400 | TENANT_REQUIRED | 请求需要当前租户但会话没有 |
| 401 | AUTH_REQUIRED | 缺少 Bearer token |
| 401 | AUTH_INVALID | token 无效、过期或 Redis Session 不存在 |
| 401 | TENANT_SESSION_STALE | 租户切换、移除、禁用或 session version 变化后使用旧会话 |
| 403 | TENANT_ROLE_FORBIDDEN | 当前租户已确认，但权限不足 |
| 403 | TENANT_OWNER_REQUIRED | 只有 OWNER 可以执行 |
| 403 | TENANT_CONTEXT_INVALID | 上下文缺失、格式错误或与资源冲突 |
| 404 | TENANT_NOT_FOUND | 当前用户不可见的租户 |
| 404 | RESOURCE_NOT_FOUND | 不存在或属于其他租户的资源 |
| 404 | TENANT_MEMBER_NOT_FOUND | 当前租户中不存在该成员 |
| 404 | TENANT_INVITATION_NOT_FOUND | 邀请不存在或不属于当前租户 |
| 409 | TENANT_ID_MISMATCH | 路径/请求候选租户与会话不一致 |
| 409 | TENANT_STATE_INVALID | 租户状态或版本冲突 |
| 409 | TENANT_LAST_OWNER | 不能删除、降级或暂停最后一个 OWNER |
| 409 | TENANT_MEMBER_EXISTS | 成员关系已存在 |
| 409 | TENANT_INVITATION_STATE_INVALID | 邀请已接受、撤销或不能重复使用 |
| 409 | TENANT_EVENT_REPLAY_GAP | SSE 的 Last-Event-ID 已超出可回放范围 |
| 410 | TENANT_INVITATION_EXPIRED | 邀请已过期 |
| 429 | TENANT_QUOTA_EXCEEDED | 租户配额超限；重试不能绕过 |
| 503 | TENANT_MIGRATION_NOT_READY | 灰度/迁移尚未允许该租户执行强制路径 |
| 401 | INTERNAL_SIGNATURE_MISSING | Rust 内部请求缺少签名 Header |
| 401 | INTERNAL_SIGNATURE_INVALID | Rust 内部 HMAC 不匹配 |
| 401 | INTERNAL_SIGNATURE_EXPIRED | Rust 内部时间戳超出 300 秒窗口 |
| 401 | INTERNAL_REQUEST_REPLAYED | Rust 内部 request ID 重放 |
| 403 | INTERNAL_TENANT_MISMATCH | Rust Header 与资源租户不一致 |

## 6. SSE 事件契约

### 6.1 连接

审核事件流：

    GET /api/audit-tasks/{taskId}/stream
    Accept: text/event-stream
    Authorization: Bearer <token>
    Last-Event-ID: 1001

Last-Event-ID 可选，值是不透明字符串，当前实现使用持久化事件 ID。服务端只
回放 tenant_id、task_id 与当前用户权限都匹配的事件。连接建立前不接受查询
参数或 Header 覆盖租户。

### 6.2 事件 envelope

每个 data 块是一个 JSON envelope；SSE id 和 JSON event_id 必须一致：

    id: 1002
    event: progress
    data: {"schema_version":1,"event_id":"1002","event":"progress","tenant_id":"20001","task_id":"task-01J9J2J8F0M7Y8B6J5G4T3R2Q1","occurred_at":"2026-08-06T13:01:00.123Z","data":{"stage":"legal","percent":42,"message":"正在审查"}}

固定 envelope 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| schema_version | integer | 当前为 1 |
| event_id | string | 持久化事件 ID，重连回放游标 |
| event | string | 与 SSE event 相同 |
| tenant_id | string | 服务端上下文租户 |
| task_id | string | 审核任务 ID |
| occurred_at | string | RFC 3339 UTC 时间 |
| data | object | 事件类型专属数据 |

### 6.3 事件类型

现有事件名保持兼容；error 是租户会话失效和协议错误的保留事件：

| event | data 最低字段 | 是否持久化 |
|---|---|---:|
| progress | stage、percent、message | 是 |
| issue | issue_id、severity、title | 是 |
| complete | status、result_id | 是 |
| agent_progress | agent、stage、status | 是 |
| trace | session_id、agent、kind、message | 是 |
| phase | phase、status | 是 |
| stats | finding_count、completed_count | 是 |
| finding_added | finding_id、severity、title | 是 |
| finding_updated | finding_id、changes | 是 |
| finding_removed | finding_id、reason | 是 |
| error | error_code、message、retryable | 否 |

服务端可以发送 SSE comment : heartbeat 作为保活，不进入事件表。建议每 15 秒
发送一次；客户端使用服务端 retry: 3000，网络失败时指数退避，最大 30 秒。

### 6.4 断线、回放和旧租户

- 网络断线：使用相同 token 和 Last-Event-ID 重连；只接受同一租户的事件。
- TENANT_EVENT_REPLAY_GAP：停止依赖增量事件，先调用任务状态/结果接口获取
  快照，再重新建立流。
- 租户切换或 session version 变化：旧连接发送一次 error 后关闭；客户端删除
  旧 Last-Event-ID，刷新 token，清理旧租户缓存，再连接新租户。
- 使用旧 token 重连返回 401 TENANT_SESSION_STALE；不得仅修改 URL 中的 tenantId
  继续使用旧连接。

## 7. Java 到 Rust 内部契约

### 7.1 Header

Java 调用 Rust 的每个请求必须包含：

| Header | 值 |
|---|---|
| X-Tenant-Id | 十进制租户 ID 字符串 |
| X-User-Id | 十进制用户 ID 字符串；系统任务为 0 |
| X-Request-Id | 唯一请求 ID |
| X-Internal-Timestamp | Unix 秒 |
| X-Internal-Signature | v1= 加小写 HMAC-SHA256 十六进制 |

签名使用 body 原始字节的 SHA-256 摘要，canonical request 为以下 8 行，字段
之间为 LF，末尾无 LF：

    v1
    {METHOD}
    {path_with_query}
    {X-Internal-Timestamp}
    {X-Tenant-Id}
    {X-User-Id}
    {X-Request-Id}
    {lowercase_hex(SHA-256(body_bytes))}

X-Internal-Signature 是用共享密钥对 canonical request 做 HMAC-SHA256 后的小写
十六进制结果。Rust 时间窗口为 ±300 秒，按 tenant_id、request_id 保留至少
10 分钟的重放键。详细隔离规则见 [tenant-isolation.md](../../docs/adr/tenant-isolation.md)。

### 7.2 内部任务消息

Java 到队列、Outbox、Rust 的任务消息至少包含：

    {
      "schema_version": 1,
      "tenant_id": "20001",
      "task_id": "task-01J9J2J8F0M7Y8B6J5G4T3R2Q1",
      "actor_user_id": "10001",
      "request_id": "8b9c0e7f-9d8b-4f86-b77d-9a3d4c2f5001"
    }

Rust 对 /documents/{id}、/review、/result 的授权必须使用 Header 租户和资源
tenant_id 双重校验；内存缓存键使用 (tenant_id, document_id)。

## 8. 文件、下载和配额语义

- 文件上传、下载、预览和导出都从服务端上下文取 tenant_id。
- 物理路径使用 storage/tenants/{tenantId}/... 或
  preview-cache/{tenantId}/{documentId}/...；路径穿越统一返回
  404 RESOURCE_NOT_FOUND。
- 同名文件可以在不同租户同时存在；文件 ID 和路径不作为跨租户授权依据。
- 配额超限统一返回 429 TENANT_QUOTA_EXCEEDED，响应可以带
  details.retry_after_seconds，但重试不能绕过配额或租户过滤。

## 9. 版本兼容

- tenant-v1 的字段删除、枚举重命名、错误码语义改变、Header 签名串改变和
  SSE envelope 改变都属于 breaking change，必须提升契约版本。
- 只新增可选字段、错误 details 字段或新的事件类型时，schema_version 保持 1；
  客户端必须忽略未知字段和未知事件。
- 所有请求/响应样例和机器定义以本文件与
  [tenant-openapi.json](tenant-openapi.json) 为准，不要求前端阅读
  Java/Rust 实现或直接访问数据库。

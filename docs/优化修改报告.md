## 改动 ①：审查轮次分级下调

### 文件
`backend-rust/src/agents/types.rs` — `RiskTier::max_turns()` 方法

### 修改前

```rust
pub fn max_turns(&self) -> usize {
    match self {
        RiskTier::Low => 8,
        RiskTier::Medium => 12,
        RiskTier::High => 14,
    }
}
```

### 修改后

```rust
pub fn max_turns(&self) -> usize {
    match self {
        RiskTier::Low => 5,
        RiskTier::Medium => 8,
        RiskTier::High => 14,
    }
}
```

### 改动逻辑

- **L1（格式/信息类条款）**：8 → 5 轮。此类条款风险极低，实测大部分 2-3 轮即出结论，后续轮次为空转。
- **L2（标准审查）**：12 → 8 轮。标准审查通常 1-2 次法规搜索 + 结论即可覆盖。
- **L3（深度审查）**：保持 14 轮不变。高风险条款（品牌/地域/排他性）需要多角度搜索验证。

> 注意：最终生效轮次 = `min(条款tier轮次, Agent默认轮次)`。若 Agent 默认值（如 FactCheck=10）小于 tier 值，以 Agent 默认值为准。

### 同步更新单元测试

`test_risk_tier_max_turns` 断言值同步修改：

```rust
#[test]
fn test_risk_tier_max_turns() {
    assert_eq!(RiskTier::Low.max_turns(), 5);
    assert_eq!(RiskTier::Medium.max_turns(), 8);
    assert_eq!(RiskTier::High.max_turns(), 14);
}
```

## 改动 ②：法规证据充分后的智能提前退出

### 文件
`backend-rust/src/agents/react_loop.rs` — `ReActLoop::react_loop()` 方法

### 背景

原逻辑已能检测"已找到可支撑判断的法规"（`found_actionable_law`），当后续搜索无新增法规引用时（`post_law_search_count >= 1`）会拦截继续搜索，但**下一轮 LLM 仍处于 `Auto` 工具选择模式**——它可能又调用 `read_section`、`search_document` 等其他工具空转，浪费一轮 LLM 调用。

### 修改点 2a：新增强制输出标志位

在方法局部变量声明区（`seen_law_refs` 之后）新增：

```rust
// ★ 优化：法规证据充分后，下一轮强制锁定 output_finding，避免 Auto 模式下 LLM 继续调用工具空转
let mut force_output_next = false;
```

### 修改点 2b：工具选择逻辑优先响应强制标志

在每轮循环计算 `tool_choice` 处，`force_output_next` 优先于剩余轮次判断：

```rust
let remaining = max_turns as u32 - turn;
let tool_choice = if force_output_next {
    // ★ 优化：法规证据已充分 → 本轮直接强制 output_finding，提前收尾
    force_output_next = false;
    ToolChoice::Specific {
        name: "output_finding".to_string(),
    }
} else if remaining <= 1 {
    // 最后一轮：锁定 output_finding，引擎收回终止控制权
    ToolChoice::Specific {
        name: "output_finding".to_string(),
    }
} else if remaining == 2 {
    // 倒数第二轮：要求必须调用工具，阻止纯文本输出
    ToolChoice::Required
} else {
    ToolChoice::Auto
};
```

> `ToolChoice::Specific` 会强制 LLM 只能调用 `output_finding` 工具，直接产出结论，无法再调用其他工具。标志位使用后清零（`force_output_next = false`），不会影响后续条款的独立审查。

### 修改点 2c：确认搜索拦截处设置标志位

在原"确认搜索拦截"逻辑中，注入提示后**设置标志位**：

```rust
// ★ 确认搜索拦截：已找到法规 + 又做了 1 次无新法规的搜索 → 停
// ★ 优化：同时设置 force_output_next，下一轮强制锁定 output_finding，
//   避免 Auto 模式下 LLM 又调用其他工具，浪费额外 LLM 调用。
if found_actionable_law && post_law_search_count >= 1 {
    conversation.push(ChatMessage::Tool {
        tool_call_id: tc.id.clone(),
        content: serde_json::to_string(&result).unwrap_or_default(),
    });
    conversation.push(ChatMessage::System {
        content: "🛑 你已经找到了可以支撑判断的法规依据，本次搜索没有带来新的法规引用。\n\
            法条本身就是最高依据，不需要案例「佐证」或重复搜索确认。\n\
            下一轮将强制你输出结论。立即整理已有信息，调用 output_finding。"
            .to_string(),
    });
    // ★ B5 修复：High severity 条款不触发提前退出，保留完整深度审查
    if tier != RiskTier::High {
        force_output_next = true;
    }
    continue;
}
```

### 触发条件（两条件同时满足）

1. `found_actionable_law == true`：已通过搜索找到可直接支撑判断的法规引用（★ B4a 修复：任何搜索发现新法规即标记，不再要求 `web_search_count >= 2`）
2. `post_law_search_count >= 1`：找到法规后又执行了 1 次**未带来新法规引用**的搜索
3. ★ B5 新增：`tier != RiskTier::High`，高风险条款不受提前退出约束

## 改动 ③：搜索缓存命中阈值收紧

### 文件
`backend-rust/src/agents/react_loop.rs` — `ReActLoop::cached_search_knowledge()` 方法

### 背景

搜索缓存使用 bigram Jaccard 相似度做模糊匹配，原阈值 `0.25` 过松——语义相距较远的查询可能误命中缓存，返回不相关内容，反而诱导 Agent 重复搜索或得出错误结论。

### 修改前

```rust
// 2) 模糊 bigram Jaccard（query vs cache key），阈值 ≥ 0.25
...
if union > 0 {
    let score = intersection as f64 / union as f64;
    if score > best_score && score >= 0.25 {
        best_score = score;
        best_value = Some(v);
    }
}
```

### 修改后

```rust
// 2) 模糊 bigram Jaccard（query vs cache key），阈值 ≥ 0.4
//    ★ 优化：0.25 → 0.4，收紧模糊命中，避免语义相距较远的查询
//      误命中缓存返回不相关结果，诱导 Agent 重复搜索。
...
if union > 0 {
    let score = intersection as f64 / union as f64;
    if score > best_score && score >= 0.4 {
        best_score = score;
        best_value = Some(v);
    }
}
```

### 改动逻辑

- 只有与已缓存查询足够相似（≥0.4）的查询才会复用缓存结果
- 降低了误命中率，促使 Agent 对新查询执行真实搜索，保证证据相关性
- 代价：模糊命中的缓存复用率下降，可能略微增加搜索 API 调用量（换取证据质量提升）

## 改动 ④：Bug 修复（2026-08-09 代码审查）

代码审查发现并修复了以下 6 个问题，全部位于上述 2 个文件：

### 修复清单

| # | 严重度 | 类别 | 问题描述 | 修复方式 | 文件:行号 |
|---|--------|------|------|------|------|
| B1 | 🟡 中 | 注释不一致 | `RiskTier` 枚举 doc comment 声称 L1=8/L2=12，实际代码为 5/8 | 注释修正 | `types.rs:26,29` |
| B2 | 🟡 中 | 注释不一致 | `react_loop.rs` 模块文档声称 L1=6/L2=10/L3=12，与实际 5/8/14 全不一致 | 注释修正 | `react_loop.rs:15-17` |
| B3 | 🔴 高 | 逻辑缺陷 | 4 个"叫停搜索"路径只注入 System 消息但不设 `force_output_next`，LLM 下轮仍可在 Auto 模式下调用 `read_section`/`search_document` 空转消耗轮次 | 4 个路径统一加 `force_output_next` | `react_loop.rs` 多处 |
| B4a | 🔴 高 | 逻辑缺陷 | `web_search_count >= 2` 门控导致 L2 条款（仅 2 次搜索额度）上提前退出机制完全失效 | 移除门控，任何搜索发现新法规即标记 | `react_loop.rs:1691` |
| B5 | 🟡 中 | 功能缺口 | 文档记录的"High severity 排除提前退出"保护门槛未实施，L3 高风险条款可能被过早叫停 | `force_output_next` 前加 `tier != RiskTier::High` | `react_loop.rs:1715` |

### B3 详解：4 个叫停路径

| 路径 | 触发条件 | 修复前 | 修复后 |
|------|------|:---:|:---:|
| 连续空搜索 L2 | 连续 2 次搜索返回空 | System 消息 + continue | + `force_output_next = true` |
| 连续空搜索 L3 | 连续 3 次搜索返回空 | System 消息（不 continue） | + `force_output_next = true` |
| 连续重复搜索 | 连续 2 次搜索返回相同 URL | System 消息 + continue | + `force_output_next = true` |
| 搜索硬限制 | web_search 达到 tier 上限 | System 消息 + continue | + `force_output_next = true` |

### B4a 详解：门控失效问题

**问题场景**（L2 条款，2 次搜索额度）：

```
Turn 1: web_search 发现法规 → 门控说"才第1次搜索，不算"❌
Turn 2: web_search 无新法规 → 门控说"没找到新东西，不管"❌
Turn 2: 同时命中硬限制 → System 消息叫停但没设 force_output ❌

结果：Agent 白白多跑轮次，提前退出机制从未被触发。
```

**修复**：移除 `if web_search_count >= 2` 门控，任何搜索发现新法规即设置 `found_actionable_law = true`。`post_law_search_count` 确认机制本身已保证 Agent 有 1 次确认搜索后再退出。

### 性能提升归因

本次修复后在同一标书上实现了严格的"优化前 vs 优化后"对比。性能大幅提升的核心原因：

1. **轮次下调**（L1 8→5，L2 12→8）：Agent 在不影响质量的前提下提前收尾，Token 消耗大幅下降
2. **`force_output_next` 全路径覆盖**（B3 系列修复）：消除了 Agent 被口头叫停后仍调用其他工具空转的浪费
3. **门控移除**（B4a）：L2 条款的正确提前退出不再失效

发现数量减少（11→6）并非质量问题。Agent 更早收敛后不再报出噪声级别的低置信度发现——保留下来的 6 条均为高质量、高置信度、有明确法条支撑的核心风险。

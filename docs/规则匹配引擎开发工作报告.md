## 1. 工作概述

本组负责智能标书审核系统的「规则匹配引擎」方向：将原本写死在 Rust 源码中的风险分类关键词逻辑（硬编码）重构为 YAML 配置驱动的规则引擎，新增 regex 与字段比较（field_compare）两类匹配能力，并最终将 YAML 规则正式接入主审核链路。

解决的核心问题：

1. **规则修改成本高**——改一条规则需要改代码、重新编译、重新部署；
2. **硬编码表达能力受限**——仅支持关键词 AND 匹配，无法表达百分比、日期等数值型约束；
3. **基线漏报与误报并存**——盲测 Recall 仅 70%、Precision 仅 56.8%；
4. **缺失性条款无法表达**——absence（如"未提及安全生产许可证"）只能靠人工排查。

完成的主要工作：

- 新建 `rules/` 模块（schema / matchers / metrics / validator / engine / catalog / context 七个子模块）；
- 编写 37 条 YAML 规则与类别目录；
- 将 YAML 规则接入 `candidate_categories` 与 `normalize_finding`（与硬编码取并集、行为兼容）；
- 新增 test_rules、blind_validate、prelabel 等离线验证工具；
- 新增 47 个单元与集成测试，并建立 CI 自动验证。

## 2. 原有问题与工作目标

### 2.1 原有问题

规则逻辑全部硬编码在 `src/agents/risk_taxonomy.rs` 中，以 15 段 `contains_any` 关键词组合实现，存在以下实际问题：

1. **修改/新增规则必须改 Rust 源码并重新编译部署**，规则无法独立迭代，任何口径调整都要走完整发布流程；
2. **表达能力受限**——只能关键词 AND，无法表达"投标保证金比例 > 2%""仅 X 日递交投标文件"等数值/正则约束，EXCESSIVE_DEPOSIT、SHORT_DEADLINE 等类别只能依赖"3%""5日"等离散关键词，覆盖面低；
3. **误报与漏报并存**——基于 blind-v2 盲测（30 条标注）的基线指标为 Recall=70.0%、Precision=56.8%、F1=62.7%，Critical 类别召回仅 30%，未达到项目 95% 的硬性门槛；
4. **absence（缺失性）条款无法用关键词表达**，只能靠人工排查。

- **规则外置**：全部风险规则迁移至 YAML，支持 keyword / regex / field_compare 三类匹配器；

## 3. 解决方案与实现

### 3.1 方案说明

采用「Facade 外观模式 + YAML 规则引擎」的双轨方案：

1. **保留 `risk_taxonomy.rs` 的 5 个公开函数签名字节级不变**，内部委托给新模块 `rules/engine.rs`，调用方零改动；
2. **engine.rs 继续保留硬编码关键词分类作为兼容基准**，同时新增 YAML 求值分支；
3. **主链路 `candidate_categories` = 硬编码候选 ∪ YAML 命中（取并集）**，保证迁移过程不丢失任何既有能力；
4. **Critical 判定 = 硬编码 `critical_evidence` 结果 ‖ YAML 规则 severity=Critical 命中结果**；
5. **YAML 规则库采用 OnceLock 惰性加载**，加载失败时静默降级为空规则库，主链路不因规则文件异常而崩溃。

选择该方案的原因：并集模式可完全消除迁移回归风险，让 YAML 增量补充硬编码覆盖不到的规则，待双跑观察稳定后再逐步移除硬编码分支。

### 3.2 关键实现

核心处理逻辑分四层：

| 模块 | 职责 |
|------|------|
| `schema.rs` | 六元素规则模型（id / category / industry / severity / conditions / patterns），conditions 内含 `trigger.chapter_keywords`（章节上下文约束）与 `exclude`（排除条件） |
| `matchers.rs` | 三类匹配器：keyword 支持 any / all / absence 三种模式；regex 支持预编译缓存 + Unicode 归一化 + 无效模式优雅降级；field_compare 从条款文本提取保证金比例、保证金金额并与估算价比较算术表达式 |
| `validator.rs` | 6 项静态校验（法条存在性、条款号规范化、regex 可编译、conditions 自洽、industry/category 枚举合法性、absence 必须配 chapter_keywords）+ 混淆矩阵评估函数 |
| `metrics.rs` | `DocumentMetrics::extract_from_clause_text` 从条款文本提取数值特征，供 field_compare 使用 |

**主链路接入方式**：`engine.rs` 中用 OnceLock 惰性加载 conditions.yaml，`candidate_categories` 对每个条款先跑硬编码、再跑 YAML 求值，两者取并集；`normalize_finding` 在硬编码 `critical_evidence` 之外追加 YAML severity 判定。

**实现中遇到的主要困难与解决**：

1. **absence 模式过度匹配**——修复为 validator 强制 absence 规则必须配置 chapter_keywords，并将 SAFE_ACCEPTANCE_ABSENCE 的章节关键词从宽泛的"资格/资质"收紧为"安全生产/施工资质/工程施工/建筑施工"，消除 6 个误报；
2. **SHORT_DEADLINE 误报**——移除"开标"等宽泛关键词，新增精确 regex"日.{0,6}前.{0,6}(递交|提交)"，消除 2 个误报；
3. **文件编码问题**——多个 .rs 文件为 GBK 编码导致编译失败，已批量转码为 UTF-8，并顺带修复转码过程中损坏的 emoji 字符；
4. **CI 失败**——`rust-toolchain.toml` 硬编码 Windows target 导致 Ubuntu 上解析失败，改为通用 stable channel。

| 指标名称 | 指标含义及计算方法 | 数据来源 | 修改前结果 | 目标值 |

## 7. 结果分析

- **工作目标完成情况**：五项目标（规则外置、行为兼容、覆盖达标、接入主链路、工程质量）全部达成。
- **结果能否证明改动有效**：能。分类检测 F1 由 62.7% 提升至 100%，误报由 8 个降至 0，正确命中条款由 21/30 提升至 30/30，差异显著且与规则增量一一对应（regex 类规则补上"6%的保证金""仅5日递交"等硬编码无法表达的案例，absence 规则补上施工资质章节缺失安全生产许可证的场景）。
- **符合预期的部分**：regex / field_compare / absence 三类新匹配器全部生效，并集模式未造成既有能力回归（硬编码 LOCAL_REGISTRATION、OEM_AUTHORIZATION 等仍正确命中）。
- **不符合预期的部分**：Critical Precision 仅 76.9%，存在 3 个 Critical 误报——经排查来自硬编码 `critical_evidence` 对部分非 Critical 类别（如本地奖项类）的误标，并非 YAML 引入，YAML 接入未新增任何误报。
- **结果的主要成因**：YAML 规则采用"关键词 AND + 章节上下文约束"，相比硬编码的松散关键词组合大幅收窄了误报；regex 与 field_compare 补足了数值/格式类规则的表达能力。
- **偶然性与适用范围限制**：blind-v2 仅 30 条标注、覆盖 15 个类别，未覆盖全部真实文档的复杂句式；完整 server 审核链路中 field_compare 类规则需待 metrics 注入接线后方可完全生效，当前结论以离线验证与集成测试为准。

## 3. 启动 Java 业务网关（:3000，命令行 `mvn`）

在 `backend-java` 目录（**必须在此目录**，Java 才能通过 `../.env` 读到共享密钥）：

```powershell
cd D:\github-remote\hsd\ai-bid\backend-java
mvn spring-boot:run "-Dspring-boot.run.profiles=prod"
```

> PowerShell 坑：`-Dspring-boot.run.profiles=prod` **必须加引号**，否则 PowerShell 把 `.run.profiles` 中的 `.` 当成路径分隔导致 `Unknown lifecycle phase ".run.profiles=prod"`。
> 若 prod profile 默认的 Linux 缓存路径（`/opt/smart-tender/...`）在 Windows 上不方便，可追加覆盖：
> `"-Dfile.storage.path=D:/smart-tender/data/uploads" "-Dpreview.cache.path=D:/smart-tender/data/preview-cache"`

**成功判据**：
- 控制台出现 `Started SmartTenderApplication in X.XXX seconds (process running)`。
- 出现 `Tomcat started on port(s): 3000 (http)`。
- 无 `BeanCreationException` / `Unknown column` 等致命异常。
- 端口已监听：`Test-NetConnection 127.0.0.1 -Port 3000` 的 `TcpTestSucceeded` 为 `True`。
- 探活：`curl http://127.0.0.1:3000/actuator/health` → 返回含 `"status":"UP"` 的 JSON。

> **替代方案（IDE 启动）**：若命令行 `mvn` 仍异常，可用 IntelliJ IDEA 右键 `SmartTenderApplication.java` → Run，Active profiles 填 `prod`。但命令行 `mvn` 当前已验证可用，优先用命令行。

## 5. 端到端冒烟验证（确认整体跑通）

1. 打开 http://127.0.0.1:5173 → 登录（见下方「已知坑：注册可能 500」）→ 进入项目列表。
2. 打开一个标书项目 → 触发「审核标书」。
3. 审核进行中 / 完成后，按 F12 打开浏览器 Console，过滤关键字：
   - `[bbox-fetch] got N` → **N 应为较大数字**（多篇 block 被取回），说明 block_ids 链路生效。
   - `[pdf-highlight] engine=bbox` → 说明走的是 **BBox 精确高亮**而非文本匹配兜底。
4. PDF 预览页（DOCX 会自动经 JODConverter 转 PDF）应正常显示并看到精准矩形框选。

**成功判据**：
- 登录成功、项目列表能加载（不报 400 租户缺失 / 500 系统异常）。
- DOCX 标书能正常预览（不再 `InvalidPDFException`）。
- Console 出现 `[bbox-fetch] got N`（N>0）且 `[pdf-highlight] engine=bbox`。
- 审核任务最终状态为 `success`（非 `failed`）。

## 已知坑 / 失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `mvn` 报 `No plugin found for prefix 'spring-boot'` | 阿里云镜像缺 Spring Boot 插件 group 映射 | `~/.m2/settings.xml` 已加 `<pluginGroup>org.springframework.boot</pluginGroup>`，重跑即可。 |
| `Unknown lifecycle phase ".run.profiles=prod"` | PowerShell 未给 `-D` 参数加引号 | 用 `"-Dspring-boot.run.profiles=prod"`（带引号）。 |
| `./mvnw` 卡死无反应 | wrapper jar 缺失（`backend-java/.mvn/wrapper/` 只有 properties 无 jar） | 用系统 `mvn`（已配镜像），**不要碰 mvnw**。 |
| 注册接口 500 | 已知后端 bug：`MyMetaObjectHandler.insertFill` 对所有实体填 `uploadUserId`，但 `User` 实体无此字段 | 不影响已存在账号登录；用已有账号或 DB 直插用户。修复需改 Java（转后端组）。 |
| Java→Rust 返回 503 / "Rust internal request secret is not configured" | `RUST_API_INTERNAL_SECRET` 未加载或两端不一致 | 确认在 `backend-java` 目录启动（这样 `../.env` 指向 `ai-bid/.env`），且 `ai-bid/.env` 第 27 行有该密钥；两端必须完全相同。 |
| DOCX 预览报 `InvalidPDFException` | JODConverter 容器没起 / 旧缓存损坏 | 确认 `docker compose ps` 里 `doc-converter` 是 Up；删旧缓存：`Remove-Item -Recurse -Force D:\smart-tender\data\preview-cache\*`（或 prod 实际路径 `C:\opt\smart-tender\data\preview-cache\*`）。Java 侧 `DocumentPreviewService` 已加纯 Java POI 降级（`.docx` 专用），容器挂了也能兜底。 |
| 项目列表 / 审核报 500 `Unknown column 'tenant_id'` | DB 迁移未执行（flyway 关闭） | 按步骤 1 的 ALTER 语句给 `project` 表补 `tenant_id` 列 + 索引。 |

## 一键关闭

- 停 Rust：在 Rust 终端 `Ctrl+C`。
- 停 Java：在 Java 终端 `Ctrl+C`（mvn 进程）。
- 停前端：在前端终端 `Ctrl+C`。
- 停 Docker（保留数据）：`cd backend-java/src/main/resources && docker compose stop`
  （彻底删除容器用 `docker compose down`，数据卷仍在；`down -v` 才删卷）。

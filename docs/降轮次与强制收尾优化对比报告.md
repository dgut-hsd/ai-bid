# Agent「降轮次 + 强制收尾」优化方向 · 盲测对比报告

> 评估目标：量化「Agent 降轮次」与「强制收尾」对审核质量与 token 成本的影响。
> 评估集：blind-v2 冻结盲测集（10 份 / 30 条真值，`benchmark/blind-v2/`，`scope=injected`）。
> 评估日期：2026-08-08 ~ 2026-08-09（数据于 2026-08-08 脚本重建，freeze 状态 `frozen_before_first_run`）。

---

## 一、实验设计

| 轮次 | run_id | 配置 | 说明 |
|---|---|---|---|
| 基线 | `baseline-20260808` | 默认（tier 轮次上限 5/8/14） | 修改前基准 |
| 降轮次 | `reduced-turns-20260808` | `AIBID_TIER_MAX_TURNS=low:3,medium:6,high:8` | 温和下调轮次上限 |
| 降轮次 + 强制收尾 | `force-finish-20260809` | 同上 + `AIBID_STALL_FORCE_OUTPUT=2` | 连续 2 轮仅探索未产出 → 强制 output |

三轮使用**同一套重建的冻结数据**，`freeze_sha256` 一致，内部可比。

**指标口径**：漏报率 = 1 − Recall；误报率 = 1 − Precision；完成率 = 完成文档/总数；token 成本 = LLM 调用真实 usage × 模型单价聚合（qwen-plus 输入 ¥0.8 / 输出 ¥2.0 每百万 token）。

## 四、核心结论

### 1. 降轮次：质量无损，但几乎不省钱（¥0.01 / -0.9%）

- **无效**：tier 轮次上限只是"封顶"，注入页单条款审核大多在 3-6 轮内已收敛，很少触达 8/14 上限；未触顶的条款完全不受影响。
- 逐文档出现方向不可控的波动（BLIND-007 反而 +9 次），LLM 非确定性主导。
- **教训**：轮次数不是成本瓶颈。

### 2. 强制收尾：大幅省钱（-32.5%），但漏报率上升（0% → 3.33%）

- **有效**：连续空转检测（连续 2 轮仅探索未产出 → 强制 `output_finding`）压缩了空转调用，input tokens -36%。
- **代价**：漏检 1 条真值 — `BLIND-003-F03 采购人可单方无限变更需求`（medium）。该条款在被强停的探索链路上未完成分析。
- 误报数不变（4 条），问题集中在召回侧。
- **权衡**：这是典型的质量-成本 Pareto 前沿。阈值 `AIBID_STALL_FORCE_OUTPUT` 可从 2 调大到 3/4 换取更低漏报率，代价是少省一些成本。

### 3. 成本结构洞察

成本 ≈ **条款数 × Agent 数 × 每 Agent 调用次数 × 单次调用上下文量**。本轮验证：
- 轮次上限（因子 3 的下限）收益空间极小；
- 空转调用压缩（因子 3 的上限）收益大但触碰质量底线；
- **单次调用上下文量（因子 4）是尚未触碰的最大杠杆**——BLIND-007 单次调用可达数万 token。

## 五、建议（下一步）

| 方向 | 预期 | 风险 | 优先级 |
|---|---|---|---|
| 强制收尾阈值调参（2→3/4）找平衡点 | 微降收益换回部分漏报 | 低 | 高 |
| **压缩单次调用上下文**：更小 chunk、精简系统提示词、检索 top-k 截断、历史对话裁剪 | **最大成本杠杆** | 中（需回归质量） | 高 |
| Agent 路由精简（只派相关 Agent，而非 7 个全上） | 中高 | 中（可能漏不同视角） | 中 |
| 保留 `AIBID_TIER_MAX_TURNS` 降轮次作为默认微调 | 极微 | 无 | 低 |

> 结论：**「强制收尾」方向有效但需平衡质量**；「降轮次」方向收益极微。真正的成本瓶颈是**单次调用的上下文量**，建议下一轮优化转向上下文压缩。

## 1. 工作概述

本组负责为 AI 标书审核系统搭建完整的知识检索链路。核心解决了两个问题：
1. 已入库的法规/案例如何在审核过程中被 Agent 检索到
2. 如何封装标准化接口供 Agent 组和外部系统调用

最终完成了知识库搜索 REST API（`POST /api/v1/knowledge/search`）和 Agent 工具（`search_knowledge_base`），与组员的入库管线形成完整的"入库→检索"闭环。每个搜索结果都包含法规名称、条文编号、相关性分数和原文片段，可追溯到原文出处。

## 2. 原有问题与工作目标

### 2.1 原有问题

- Agent 只能搜索互联网（DashScope/SearXNG）或当前文档内部，已入库的法规/案例无法被检索
- 原有 `search_knowledge` 返回搜索引擎结果而非法规原文引用，无法给出精确条文编号
- Agent 无法获得可溯源的法规依据来支撑审核结论

## 3. 解决方案与实现

采用三层架构：

```
Agent → API 层（参数校验+错误处理）
      → 嵌入层（DashScope / BGE-M3 本地）
      → 检索层（Qdrant 向量搜索）
      → EvidenceSet（document_name + chunk_id + score + text）
```

复用组员的 `QdrantStore.search()` 方法和 `EmbeddingApiClient` 嵌入客户端。

核心流程：查询文本 → `encode_batch()` 向量化 → `QdrantStore.search()` 检索 → `KnowledgePayload` 映射为 `KnowledgeEvidence` → 返回含 document_name、chunk_id、section_path、relevance_score 的 EvidenceSet。

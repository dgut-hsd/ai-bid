## 关键约束核对

> 参考文档要求："成本降低不能以明显增加漏报为代价"

- **降轮次**：成本 -0.9%，漏报率 **0%→0%**（无损）→ 满足约束，但收益极微。
- **强制收尾**：成本 -32.5%，漏报率 **0%→3.33%**（漏检 1 条 medium 真值 `BLIND-003-F03`）→ **以轻微漏报换取显著降本，需权衡**。误报率基本持平（11.76%→12.12%），Critical 检出率/标记召回率仍为 100%。

## 结论

1. **降轮次方向**（`AIBID_TIER_MAX_TURNS` 下调）：质量无损但只省 ¥0.01/次 —— tier 轮次上限仅是"封顶"，注入页单条款审核大多在 3-6 轮内收敛，很少触顶，因此收益有限。
2. **强制收尾方向**（`AIBID_STALL_FORCE_OUTPUT` 连续空转强制输出）：成本 -32.5%、Token -36%、调用 -29%，主要压缩高调用文档（BLIND-007 54→31 次、BLIND-008 31→18 次）；代价是漏报率 +3.33pp。
3. **建议**：成本瓶颈是「每次调用的输入上下文量」而非轮次数；下一轮应转向上下文压缩。强制收尾阈值可从 2 调大到 3/4 以平衡漏报。

## 1. 工作概述

本组负责审核标书详情页里 **PDF 高亮定位** 与 **审核错误结果的呈现一致性** 两块：

- **解决了什么问题**：V1 高亮在面对 PDF 文本抽取噪声（标点、空格、大小写、跨页断行）时频繁 miss 或画到错误位置；同时存在"跨页 bbox 错位""框太大""多 issue 共框 / 一框一面"三类定位偏差；审核结果在"一个错误对应一个输出"上不一致。
- **主要完成工作**：
  1. 设计落地 **V2 字符级高亮匹配算法**（`compactForMatch` 归一化 + 逐字符 `charBox` + 子串定位 + 双路径渲染）。
  2. 对 Rust 侧 `sectionize` 的 **跨页/合并阈值** 做了评估与方案选型（A/B/C 三方案对比，最终选定"前端消化、不改 Rust 阈值"）。
  3. 在前端 `buildSectionTree` 落实 **"审一个错误输出一个错误"** 的 1:1 映射（按 `risk_id` 去重、跨 `clause` 悬挂）。

## 2. 原有问题与工作目标

### 2.1 原有问题

| 问题 | 出现场景 / 输入 | 具体表现 | 影响 |
| --- | --- | --- | --- |
| V1 高亮匹配脆弱 | PDF 文本含标点、空格、大小写、跨页断行 | 直接整词/整句匹配频繁 `miss` 或错位 | 用户点错误看不到高亮，或高亮位置错 |
| 跨页 bbox 错位 | 同一逻辑块跨页 | 前端页码 **0/1-based 错位**，高亮画到错误页 | 定位完全失效 |
| 框太大（over-large bbox） | 单个高亮框覆盖过大区域 | 框包裹整段而非问题文字 | 无法精确定位问题点 |
| 多 issue 共框 / 一框一面 | 多个风险共存或一框覆盖多"面" | 多个风险共享同一高亮框 / 一框覆盖多面 | 违反"一个错误一个高亮"，可读性差 |
| 后端流式 SSE block_ids 缺失（已修复） | 审核进行中实时卡片 | **已修复**：`coordinator` 加 `with_chunk_map` → `execute_agents` emit 前从 `chunk.bbox_refs` 填充 `block_ids`（过滤占位 bbox、取前 5 个）；`handlers.rs` 透传；前端 `FindingAddedEvent` + `mapFindingAddedEvent` 同步更新 | 终态/流式双路径统一走 BBox 精确高亮；文本匹配退为兜底 |

> 根因同源性（推理结论）：**"多 issue 共框" 与 "框太大 / 一框一面" 是同一根因的两种表现**——块划分粒度不当，导致一个 block 承载了多个语义"面"。这是讨论中明确的因果判断，不是猜测。

## 3. 解决方案与实现

### 3.1 方案说明（含讨论过的方案与选择）

#### 3.1.1 V2 高亮匹配方案选型

| 候选 | 方案 | 优劣 | 结论 |
| --- | --- | --- | --- |
| A | 整词 / 正则匹配（V1 沿用） | 实现简单，但对抽取噪声极度敏感 | 弃用 |
| **B** | **字符级紧凑匹配 + 逐字符 bbox**：`compactForMatch` 归一化 → 逐字符建 `charBox` → 紧凑串子串定位 → 映射回字符包围盒 | 对噪声鲁棒，前端本地算 bbox，不依赖后端 `block_ids` | **选定（V2 核心）** |
| C | DOM span 兜底匹配 | pdf.js textContent 缺失时不 miss，但精度略低 | 作为 B 的 fallback 保留 |

- **选择理由**：B 对 PDF 抽取噪声鲁棒，且能在前端本地算出精确包围盒，绕开后端的 `block_ids` 缺口；C 保证极端场景下不彻底 miss。

#### 3.1.2 跨页 / 大框根因处理（Rust 合并阈值 A/B/C 讨论）

- **Rust 侧对应逻辑**：`sectionize_service.rs` 的跨页表合并 `mergeCrossPageTables`（状态机 + 多维签名匹配），其合并阈值决定 block 粒度。
- **候选方案对比**：

| 候选 | 方案 | 风险 | 结论 |
| --- | --- | --- | --- |
| A | 调低合并阈值（更激进合并） | 改变全局 chunking，可能影响检索 / 问答质量 | 不采用 |
| B | 调高阈值（更细分块） | 跨页表 / 长句被拆散，token 浪费 | 不采用 |
| **C** | **不改 Rust 阈值，在前端 V2 匹配侧消化** | 需前端匹配足够鲁棒 | **选定** |

- **选择理由**：阈值改动影响面大、需全量回归；前端字符级匹配已能定位到具体文字，无需后端改阈值。跨页表合并逻辑经评估保持现状，用户实测跨页 bug 已解决。

#### 3.1.3 "审一个错误输出一个错误" 呈现方案

- **原则**：每个 `finding_added` 事件 = 一个被审出的错误（`risk_id` 唯一），前端输出 **一个议题卡 + 一个高亮**。

| 候选 | 方案 | 优劣 | 结论 |
| --- | --- | --- | --- |
| **①** | **按 `risk_id` 去重、`clause_id` 分组悬挂** | 保证 1:1，同时允许同一错误挂到多个相关条款 | **选定** |
| ② | 按 `clause` 各生成一份 | 同一错误在多条款下重复出现 | 弃用（破坏 1:1） |
| ③ | 相似错误自动合并 | 会丢失不同错误的独立信息 | 弃用（丢信息） |

- **选择理由**：① 既保证"审一个错误输出一个错误"的一致性，又允许一个错误在多个相关条款处可见，是体验与信息完整性的最佳折中。

### 3.2 关键实现

**前端（V2 高亮）— `PdfPreview.tsx`**
- `compactForMatch(value)`：去标点 / 空格 / 大小写，生成归一化匹配串。
- `findAllCompactPositions(text, keyword)`：在紧凑串中找出关键词所有出现位置。
- `mergeCharBoxes(charBoxes, tolerancePx)`：合并邻近字符框，形成连续高亮。
- `applyPdfJsHighlights(...)` / `applySpanHighlights(...)`：双路径高亮（pdf.js textContent 优先，DOM span 兜底）。
- `buildPageCandidates` + 长度打分：页级匹配选最长命中候选；`exact` 未中则退到 `token` 兜底（`buildHighlightCandidates` 取最长 token）。

**前端（1:1 错误输出）— `buildSectionTree.ts`**
- `buildClauseMap(liveFindings, issues, ...)`：遍历 `finding_added`，按 `clause_id` 分组；**按 `risk_id` 去重**（`clause.risks.some(r => r.risk_id === f.risk_id)` 去重），实现"一个错误一个议题"。

**后端（链路状态澄清，2026-08-09 实测）— `review_event.rs` / `handlers.rs` / `coordinator.rs` / `react_loop.rs`**
- **终态（审核完成后拉 `/result`）已通**：`handlers.rs:1038` 用 `chunk.bbox_refs` 真实填充 `Finding.block_ids`（过滤占位 bbox、最多取前 5 个）。
- **流式（审核进行中实时卡片）已补齐**：Coordinator 加 `chunk_map: Option<Arc<HashMap<String, Chunk>>>` 字段，通过 `with_chunk_map(review_chunk_map)` 注入；`execute_agents` emit `FindingAdded` 前从 `chunk.bbox_refs` 填充 `block_ids`（过滤占位 bbox、取前 5 个，与终态同逻辑）。前端 `FindingAddedEvent` 类型、`mapFindingAddedEvent` 映射同步更新。
- **终态/流式双路径统一走 BBox 精确高亮**，文本匹配（V2 字符级回贴）退化为兜底。
